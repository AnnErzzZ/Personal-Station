# 序仓 ERP MVP

入口：`http://localhost:3000/erp`。

## 本地运行

在项目根目录使用现有环境：

```powershell
npm run dev -- --hostname localhost --port 3000
```

打开 `/erp`。若预览已经运行，直接打开即可，不重复启动。

## 功能导航

一级模块按业务领域分类，二级功能打开具体页面：

| 一级模块 | 二级功能 |
| --- | --- |
| 销售管理 | 销售订单、待出库、销售退货 |
| 采购管理 | 采购入库、采购退货 |
| 库存管理 | 库存查询、库存盘点、库存流水 |
| 基础资料 | 客户管理、商品管理、供应商管理 |

一级模块可以折叠或展开。顶部面包屑展示“工作空间 → 一级模块 → 二级功能”。从客户查看订单、从商品查看库存等跨模块操作，会自动展开目标模块并定位对应页面。

商品管理维护名称、编码、单位和参考售价；新商品默认零库存。日常补货使用采购入库。旧商品的期初或零库存启用统一在库存查询的“期初设置”中完成。原有商品、订单和流水升级后保留。

## 中文字号基准

- 正文、表格内容与表头、菜单、按钮、表单标签：14px。
- 辅助说明、时间、商品编码、计数：最低 12px，移动端也保持这个下限。
- 区块标题 16px，弹窗标题 18px，桌面页面标题 28px。
- 手机端表单输入文字 16px；控件随文字增加高度，表格在自身容器内横向滚动。
- 辅助文字使用较深的灰绿色，保持字号放大后的层级和可读性。

这是本项目的界面设计基准。参考 [Ant Design 字体规范](https://ant.design/docs/spec/font-cn/) 与 [字体令牌](https://ant.design/docs/react/customize-theme-cn/)，不将其表述为所有中文界面通用的强制标准。

## 已实现

- 销售：新增客户、多商品开单、保存与编辑草稿、提交订单、填写原因取消、详情和操作历史。
- 客户管理：查看全部客户，按名称、编号、联系人或电话搜索；新增及编辑客户名称、联系人和电话；查看该客户的关联订单，并支持清除客户筛选。
- 出库：待出库列表、交接确认、整单扣减、缺货校验、重复操作保护。
- 库存：新增商品、一次性期初库存、商品查询、低库存筛选。
- 流水：按商品和业务类型筛选，展示变动数量与变动后库存，点击出库单号追溯订单。
- 本地保存：刷新保留，同浏览器多标签同步，JSON 工作区备份导出。

## 快速体验

首次打开会自动载入明确标注的办公用品示例工作区：6 种商品、3 个客户、4 笔不同状态的订单。

1. 在销售订单中新建一笔“人体工学办公椅 30 把”的订单，选择示例客户并保存草稿。
2. 在详情中提交订单，此时椅子库存仍为 100。
3. 点击确认出库，核对商品后点击“确认交接并出库”。
4. 进入库存管理，椅子库存应为 70；进入库存流水可查看关联出库记录。
5. 再尝试出库 80 把椅子，应显示缺少 10 把，整单不扣减。

若已处理示例工作区中的其他椅子订单，起始数量会相应改变，以页面实际库存为准。

## 第一版边界

这是可操作的本地单用户 MVP，数据存在当前浏览器 IndexedDB 中。不同设备、浏览器和站点地址不共享数据，清理站点数据会删除本地记录。导出功能用于保存 JSON 备份；当前不提供备份导入。

没有登录认证、服务端数据库及真实员工权限。销售和仓库是业务操作分工，当前由同一个“本地用户”完成。不能将此版本当作多员工共同使用的生产 ERP。

“客户管理”维护的是交易客户资料，不是员工登录账号。联系人和电话为选填，原有仅包含名称的客户资料会直接保留。编辑客户不会改变客户编号、订单关联或库存。有效订单金额只计算待出库和已出库订单，客户订单列表包含所有状态。

单仓库、整单一次出库、不预占库存。数量限整数，金额使用人民币并按分计算；订单金额不代表实际收款。低库存提示阈值为 10 个销售单位。

采购订单、退款、坏品库存、退货入库更正、期初单据更正、已出库更正、财务和制造尚未实现。日常补货使用采购入库，入库录错可整单冲销，实物账实差异通过库存盘点处理。期初库存只能录入一次；出库确认后没有撤销入口，确认前应核对清楚。

## 商品维护和列表筛选

商品管理支持编辑名称和参考售价，以及确认后启用／停用。已有订单或库存流水的商品锁定编码和单位。停用不删除记录、不调整库存；已有待出库订单继续履行，已有草稿需移除停用商品或先重新启用。参考售价只作为后续开单的默认价，历史单价不回写。订单商品资料保留快照，旧记录在首次商品编辑前补齐。

十一个列表均提供业务筛选器和“重置筛选”。销售订单及待出库按客户、商品、发货日期筛选；库存按状态及单位；盘点按状态、商品及创建日期；流水按商品、类型及日期；客户按订单关联及联系方式；商品按启用、期初状态、单位及供应商。条件与关键词取交集，日期含当天；切页重置条件，跨模块链接可携带指定条件。移动端双列筛选且输入为 16px。

业务及筛选规则验证：`node --test app/erp/model.test.mjs app/erp/filters.test.mjs`。完整浏览器验收还覆盖商品编辑、停用／启用、刷新保留、六页筛选交集与重置，以及桌面和手机布局。

## 采购入库操作

1. 在“采购管理 → 采购入库”新建入库单，选择供应商、收货日期，并填写商品、实收数量、采购单价。可在本单内快捷新建供应商和商品，已填内容保留。
2. 保存入库草稿，库存保持原值；核对实物后点击“确认入库”，再确认收货，库存及流水一起更新。
3. 从详情查看库存或本单流水，流水单号可返回原单。采购单价单独登记，商品参考售价保持原值。
4. 录入错误时，对已入库单填写原因并整单冲销；库存不足则整单阻止。冲销保留原单与负数流水，可建立关联更正单。实际退回供应商使用采购退货单；已发生实际采购退货的原入库单不能整单冲销。
5. 供应商管理提供名称、联系人及电话维护、启用／停用、关联入库单查询；入库单和供应商均支持组合筛选及重置。

入库状态为草稿、已入库、已取消、已冲销。采购金额用于本单记录，尚未接入成本估值、应付和付款。收货日期可补填过去日期；库存按实际确认时间生效，流水保留收货日期及实际记账时间。

库存准备显示“已就绪”或“待设置”，新商品默认以零库存就绪，旧待初始化商品需录入期初或明确确认零库存启用。该选择写入期初流水；采购、销售及冲销均保留独立来源。

## 商品供货关系

在“基础资料 → 商品管理”新增或编辑商品时，可勾选多家供应商，并指定一家默认供应商。支持查找供货方，取消默认供货方关联会同步清空默认设置。商品列表支持按关联供应商或“尚未关联”筛选。

在“供应商管理”查看供货商品数量，点击“查看供货商品”进入带筛选的商品列表。已有入库单通过单独入口查询。

采购入库选定供货方后优先显示关联商品；先选商品且供应商为空时带入有效默认值。已经选定的供应商保持不变。其他商品仍可临时采购，界面会提示核对，确认入库记录临时采购商品并保留操作历史，供货资料保持原值。修改供货关系不会回写历史单据或库存。

已停用默认供货方保留配置并标明状态，新单不自动选用。旧商品可保持未关联。验证供货关系规则：`node --test app/erp/supplier-links.test.mjs`，完整操作包含在 `verify-purchase.mjs` 中。

## 库存盘点操作

1. 打开“库存管理 → 库存盘点”，点击“新建盘点单”。选择本次清点的商品，按实物填写实盘数量；实物为零须填写 0，不默认带入账面数量。
2. 系统展示账面、实盘及差异。有差异的商品须填写原因，再保存盘点草稿，库存保持原值。
3. 在详情核对商品和差异，点击“确认盘点”，勾选已复核并最终确认。盘盈增加库存，盘亏扣减库存；零差异保留盘点单，不生成数量流水。
4. 若清点后发生进出库等业务，编辑草稿并逐行点击“重新核对”。这会读取最新账面数量，并清空该行实盘数量及原因，须重新清点后填写。只看余额相同仍可能存在中途进出库，最终按流水基准检查。
5. 已确认结果只读。通过“查看本单流水”追溯盘盈、盘亏，点击流水单号返回盘点详情。草稿可填写原因取消。

支持 1 至 100 种已初始化商品，包括已停用商品；数量为 0 至 1,000,000 的整数。本期不冻结仓库业务、不回算历史库存、不计算财务损益。确认基于最新事务数据，重复确认不再次调整；草稿修订号阻止旧页面覆盖其他页面的更新。手机端盘点商品逐项排列。

业务规则验证：`node --test app/erp/counts.test.mjs`。实际浏览器验收：`node scripts/preview-qa/with-chrome.mjs app/erp/verify-counts.mjs`。


## 销售退货操作

1. 从已出库销售订单详情点击“创建退货单”，或进入“销售管理 → 销售退货 → 新建退货单”选择原单。
2. 选择本次退回的原单商品，填写正整数数量及逐行原因。实收日期在货未到时可空，保存草稿不改库存、不占可退额度。
3. 收到并验收实物，编辑为本次实际合格数量，填写当天或过去的实收日期并保存。未收到或不合格商品从本单移除，余下以后另建单。
4. 点击“确认退货入库”，核对商品和数量，勾选已收妥并验收合格，点击“确认验收并入库”。确认成功才整单增加库存及流水，结果只读。
5. 从退货详情查看原订单、库存或本单流水。原订单保留已出库及原金额，另显示退货摘要和关联单据；退款后续处理。

每张退货单只关联一个已出库订单，允许部分及多次退货。可退量为原出库数量减去累计已入库退货，确认按最新额度校验；其他订单出入库不影响原单可退量。同单重复确认只入库一次；不同单据同原单、日期及商品数量组合出现疑似重复时，必须人工核对后继续。该提醒不能识别全部重复登记，请核实实物及已有单号。

草稿可填写原因取消，额度不足的旧草稿也能取消。多页面同时编辑时，旧修订不可覆盖新明细。停用原单商品可退回并保持停用。退货会改变库存流水，相关未确认盘点须重新清点。

本期仅接收合格品，坏品需另行隔离跟进；平台自动同步、退款、换货及退货入库冲销更正尚未实现。不同销售单位不合计为一个总数量。日期按实际确认时间记账，实收日期不回算历史库存。

业务验证：`node --test app/erp/sales-returns.test.mjs`。浏览器验收：`node scripts/preview-qa/with-chrome.mjs app/erp/verify-sales-returns.mjs`，新脚本可通过 `PREVIEW_URL` 指定完整 ERP 预览地址。验收记录及桌面／手机截图位于 `artifacts/erp/returns-*.log` 与 `artifacts/erp/sales-return-*.png`。


## 采购退货操作

1. 从已入库单详情点击“创建采购退货单”，或进入“采购管理 → 采购退货”新建并选择来源。原供应商自动带入，保存后来源固定；支持原单商品部分、分次退回。
2. 填写正整数数量及每行原因，可先不填实际退货日期。系统分别展示原单剩余可退额度、当前库存和当前最多可出库量。缺货可存草稿，但不能超过原单额度，草稿不占库存或额度。
3. 与原供应商协商，核对本次实际实物交接量，填写不早于原收货日且不晚于今天的退货日期并保存。
4. 点击“确认采购退货出库”，明确勾选供应商已同意、实物已核对并交接，点击“确认交接并退货出库”。成功后整单扣库存并生成采购退货流水，结果只读。
5. 详情可查原入库、商品库存、本单流水及该供应商全部退货。供应商管理增加“查看采购退货”，原入库显示关联退货与未退／部分／全部退货摘要；原实收、采购价和金额保留。

累计退回不超过来源实收，最终还须有足够的当前库存；不同入库单共用商品余额，但来源额度独立。系统不追踪库存的供应商或批次归属，须人工核对实物和供应商接受范围。停用的原供应商或商品仍可按历史单退回，保持停用及原快照。

同单重试只扣一次，不同单据同来源、日期及商品数量组合须核对疑似重复；人工继续仍校验额度和库存。修订号阻止旧页面覆盖或误确认，所有明细在同一事务成功或失败。

原入库一旦有实际已出库采购退货，“冲销入库”即被阻止。只有草稿时可以冲销，之后旧退货草稿不能出库，但可以填写原因取消。采购退货会使相关未确认盘点需要重新核对，即使之后补货使余额恢复也一样。

本期不处理供应商签收、退款、应付、质量库存或采购退货冲销更正；未入库拒收不扣已有库存。退货单确认失败时先核查单据状态和实物，重试同一单号。

业务验证：`node --test app/erp/purchase-returns.test.mjs`。浏览器验证：`node scripts/preview-qa/with-chrome.mjs app/erp/verify-purchase-returns.mjs`，可用 `PREVIEW_URL` 指定完整预览地址。验收记录与桌面／手机截图位于 `artifacts/erp/purchase-returns-*.log` 和 `artifacts/erp/purchase-return-*.png`。
