# Figma 作品集案例编排

把真实项目材料编排为有阅读节奏、可追溯、可继续编辑的 Figma 案例。复用选择方法和制作流程；配色、设备、页数与业务叙事按项目决定。

用户已经明确指定页数、配色、视角或版式时，先在这些约束内完成；可以解释取舍并提出替代建议，不擅自改成另一套页数或风格。以下默认选择用于未定方向的部分。

## 按任务读取

- 新建案例、确定页序或选择构图：读 [方法论](references/methodology.md)。
- 标题难读、目标空泛、加粗过多、分组松散或需要逐项引出说明：读方法论的「页序」「视觉层级与分组」「逐项说明」及「文案」部分。
- 实际操作 Figma、套样机、处理字体或局部裁切：读 [制作与验收](references/figma-production.md)，并先加载当前环境的官方 `figma-use` 技能；整页搭建再加载 `figma-generate-design`。本技能不代替官方工具文档。
- 需要复用实施助手的已验证样式或素材：读 [实施助手示例](references/implementation-assistant-example.md)。其中尺寸、节点与路径是案例记录，使用前核对。
- 开始新作品时复制 [项目工作表](assets/case-worksheet.md) 到该项目资料目录，只填写本次需要的部分。

## 执行顺序

1. 确定产品定位、受众、个人贡献与已知结果。区分产品原稿、作品集呈现与产品改版；先读取现有事实和素材记录。
2. 给拟用界面建立「能证明什么／不能证明什么」的简表。每页先写一个要表达的设计判断，再选择支持它的界面。
3. **每页视觉设计前必须找具体参考，并实际查看对应片段。** 建立逐页参考映射，记录原作／作者、链接或用户参考图、查看片段、借鉴点与应用位置；同一参考可支持多页，但每页都要说明适配依据。只给封面找参考，后续页面凭空设计，不符合本方法。
4. 在该页参考已有查看记录后，完成代表页与基础样式，再逐页继续「找参考 → 查看并选定片段 → 结合真实内容设计 → 截图对照」。用户已确认的参考可直接沿用；授权直接改稿时不必逐页等待批准。避免每页都用三张完整手机；关键入口在底部就使用底部裁切。
5. 保留原稿和真实截图，制作分层样机与原生文字。对齐可见机身边缘，按实际有效信息控制特写尺度。
6. 每轮相关修改返回受影响节点，截图验收，修正已发现的问题。通过后记录采用结果与来源，不为仪式重复截图。

## 关键判断

- 逐页参考是设计前提，统一风格和已完成的代表页不能代替后续每页的参考。尚未找到或无法查看参考的页面可以继续整理内容和素材，但先不完成其视觉定稿；记录缺口并换可查看的来源，不编造链接或借鉴记录。
- 展示包装不能代替产品界面优化。只获授权改作品集时，复制原稿用于展示，保留源页面。
- 一页内容只有一个薄弱弹窗时，先补足原稿能证明的发现、定位、处理链；仍然不足就合并页面，不编造功能凑篇幅。
- 完整样机交代上下文，特写解释决策。把一个小提示条放大数倍通常会破坏尺度；优先在保留机框的裁切窗口里呈现。用户明确要求试验时保留对照，不把推荐变成禁令。
- 所有展示卡片遵循同一套材质；色值规范中的真实色块保持原色，承载它的底板可以改暗。
- 视觉优化要改变焦点、阅读顺序或图文关系。只换渐变和卡片材质时，按实际范围报告，不把换色称为整篇排版完成。
- 需求与痛点先讲清楚，再用具体目标回应。用户指定逐项解释时保留对应粒度，压短说明，避免擅自把六项合成三组。
- 正文默认使用常规字重；用少量主题文字区分层级。共同需求须有清楚的归组理由和邻近关系，不能只在页底放一个总标题。
- 正文与设计点靠近对应图；说明文字的左边缘对齐可见机身或裁切卡内容列，不对齐 PNG 的透明边距。
- 单次演示写单次演示；口述基线注明来源。用时缩短与效率提升不同，先计算再写。未确认的未来计划不能写成已承诺的项目内容。
- 标题用简短、直白的主题词，做法和理由放正文。正文通常一句到两句；删掉重复标签和口号式概括，有阅读价值的说明保留。

## 完成时交付

交付已检查的 Figma 页面入口，以及项目自己的页序、素材和逐页参考映射。逐页核对参考是否实际查看、借鉴点是否落实，避免把事后补链接当作设计依据。报告实际完成范围；事实缺口保留在工作记录里，向用户明确指出，避免把待确认内容包装成成果。此方法不自动授权发布网站、分享文件或投递作品集。
