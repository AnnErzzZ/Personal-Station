# Figma 制作与验收

本文件记录该类作品集的操作约定与易错处，不复制完整 Plugin API。执行前加载官方 `figma-use` 并以当前工具可用能力为准；整页搭建同时读取 `figma-generate-design`。

## 文件与图层结构

保留「产品原稿」与「作品集展示」两个区域。新增案例时先核对文件、Page 和目标容器；只有用户要新文件时才创建文件，不因换案例就复制整个工作区。

推荐关系如下，名称可按项目调整：

```text
作品集／项目容器（纵向 Auto Layout）
  01／项目介绍
    背景
    标题与简介
    主视觉／设备外壳／屏幕与蒙版
  02／项目背景
    背景
    标题与正文
    内容／卡片／说明与图示
  后续章节……
```

章节之间、相关卡片、说明列使用 Auto Layout。绝对坐标用于背景、SVG 几何、卡片内部裁切、透视贴图等视觉定位，不用它代替应有的结构关系。

修改已有稿时读取当前尺寸、字体与材质，再做局部更新。需要对照时保留一个清楚命名的旧版并隐藏；隐藏内容不参与流式布局。避免把多个历史版本都命名成「当前」。

用户可能同步手动调整。每轮先核对目标节点的当前内容与样式，按本轮范围修改；不要用旧脚本整页重建来覆盖新改动。多个线程分工时，交接中写清各自页面；发生接手时先检查对方状态，避免同时修改同一页。共享变量和主组件不因一页样式修正而批量重设。

## 每次工具调用的约定

1. `use_figma` 每次调用显式切换到目标 Page，一次调用只切换一次。只读取所需子树，避免全文件批量载入。
2. 文本修改前，从节点当前 `getStyledTextSegments(['fontName'])` 获取字体并 `await figma.loadFontAsync`。移动含文字的容器也先加载相关字体。
3. 字体名和字重来自文件或 `listAvailableFontsAsync`；不靠猜测补 SemiBold 等名称。
4. 新节点先挂到正确父层，再设置 `FILL`；固定宽度正文 `resize` 后再设 `textAutoResize='HEIGHT'`。`resize` 可能重置 sizing，顺序不可反。
5. fills、strokes、effects 取副本后重新赋值；RGB 使用 0–1，透明度放 paint 的 opacity，渐变 stop 使用 RGBA。
6. 返回全部新建、修改节点 ID，连同名称、关键尺寸、状态和必要文本。嵌套创建的 SVG 子节点也计入新建列表。
7. 工具报错先按 `safeToRetryWithoutCanvasRead` 判断是否需要重读画布；不能假设失败调用没有产生局部修改。

遵循当前官方工具限制，不使用未支持的 `loadAllPagesAsync`、`setPluginData`、`figma.notify` 或 `createImageAsync`。图片导入使用当次可用的官方资产工具；不把 cookie、token 或临时资产 URL 写入项目资料。

## 横向容器高度塌缩

横向 Auto Layout 若沿用固定的交叉轴高度，仅把主轴设为 `AUTO` 会让宽度随内容变化，高度仍可能只有创建时的 10px。典型症状是文字已经按内容长高，但行、编号标题组或底部并列组仍很矮，下一行压在上一行上。

先读当前轴向与尺寸，区分有意固定尺寸的容器和应随正文增长的容器。固定宽度的横向说明行可使用以下设置；真实 API 以当次官方文档为准：

```javascript
const row = figma.createAutoLayout('HORIZONTAL');
parent.appendChild(row);
row.resize(contentWidth, 1);
row.primaryAxisSizingMode = 'FIXED';
row.counterAxisSizingMode = 'AUTO';
```

同类纵向内容列通常固定宽度、主轴随内容增长。先完成挂载、尺寸和正文设置，再恢复所需的自适应模式，因为 `resize` 可能重置 sizing。嵌套编号组、说明行、并列组与外层比较行都要核对，不能只修最外层。

页面边界检查通过仍可能存在内部重叠。另查容器是否包住可见子项、行与行是否重叠、页脚是否根据内容更新，再查看整页截图；不把「没有超出页面」单独视为通过。

## 文字、字形与真实截图

作品集标题、正文、编号和设计点优先用原生文字。产品画面优先复用原稿组件或克隆屏幕；需要跨字体保持原貌时，可以将展示副本导出为带轮廓文字的 SVG 再导入。轮廓字可编辑路径，但已不是可修改文案的文本，交付时说清。

手册和内容照片作为真实图像保留。产品图片未加载时核查原始 imageHash、填充、蒙版和可见性，不用绘制占位渐变掩盖缺图。源图没有图像时回到素材来源补齐，暂缺就保留记录。

### 用户字体在工具端不可用

桌面能显示的本机字体不一定在远端编辑工具可用。先按现有节点读取字体并尝试加载；报缺失后核对可用字体，不反复重试同一字体，也不把标题缺失扩展成整页正文换字体。

保留用户现有字形。需要新增同款标题且已有本机字体文件时，可仅将必要标题生成并导入为原生矢量轮廓；正文继续保持原生文本，原始字体文件位置和可重新生成的标题素材放在项目记录。只有路径时明确说明它能编辑字形路径，不能直接输入新文案。用户已指定文本可编辑时，应满足该要求；工具暂无法做到就说明限制，不把轮廓标题称为原生可编辑文字。

加载和修改限定在本次会变动的节点。克隆或移动含文字的容器前也核对其字体；标题已是矢量时，不对它应用 TextNode 的批量字体操作。

## 逐项旁注与引线

从实际内容节点的 `absoluteBoundingBox` 读取目标区域，将其转换为旁注舞台坐标。例如纵向锚点可由 `目标框.y − 舞台框.y + 目标框.height / 2` 得到；不要沿用旧版页面的硬编码坐标。

旁注内部的编号、短标题、说明用 Auto Layout。整条旁注与引线可按证据位置绝对定位，这是空间标注关系；不要把普通正文也改为逐字绝对摆放。先测旁注真实高度，再检测相邻旁注是否相交；目标过近时移动旁注并调整引线，保留正文阅读尺度。

引线放独立层，核对它的起点、终点与对应内容。完整界面仍使用真实原生副本或素材，不重画数字去匹配解释。未展示的展开内容保留为入口说明。

## 可复用的材质操作

下面的函数在 `use_figma` 中使用，传入当次已核对的节点对象。它只复制表现，不会同步来源卡片的业务文案和布局：

```javascript
function copyCardMaterial(source, targets) {
  const copy = value => JSON.parse(JSON.stringify(value));
  const mutatedNodeIds = [];
  for (const card of targets) {
    card.fills = copy(source.fills);
    card.strokes = copy(source.strokes);
    card.effects = copy(source.effects);
    card.strokeWeight = source.strokeWeight;
    card.strokeAlign = source.strokeAlign;
    mutatedNodeIds.push(card.id);
  }
  return { mutatedNodeIds, createdNodeIds: [] };
}
```

更换浅色底板为深色材质后，字体、字形矢量、表格线、色块边框一起适配。按语义选择主文字、辅助文字与重点色；不要遍历整页把所有深色都变白，那会连规范色块和产品内容一起改掉。

## 正面样机与裁切卡片

先读取设备官方屏幕坐标、裁边界和蒙版。原图裁掉透明外边后，屏幕位置也要减去裁边原点；之后机身和屏幕一起按比例缩放。

屏幕、外壳和刘海／灵动岛等遮挡分层。屏幕内轮廓蒙版与圆角裁切配合，检查四角露白、状态栏重复、刘海位置和机身遮挡。完整屏与局部屏使用同一个设备族。

特写结构可用「卡片 → 左说明列＋右裁切窗口 → 完整设备与真实界面」：窗口 `clipsContent=true`，设备按关键位置移动。顶部证据露顶部机框；底部入口露底部机框；半屏展示保留宿主的一部分。

对齐按可见机身边缘计算。示例：机身容器 x=100，PNG 左侧透明边距缩放后为 12，则左对齐线是 112，不是 100。卡片内部已有明确文字列时可以对齐内容列，两种对齐基准在一页中保持一致。

## 写实笔记本与手册

1. 根据参考先确定相机角度、屏幕倾斜、机身体积和台面在画面中的占比。
2. 优先使用已授权且匹配视角的样机。需要生成场景时加载 imagegen 技能，用参考约束机身、空屏、光照、台面与接触阴影。
3. 真实截图四角对应屏幕四角，避开刘海、边框和前景机身。斜角需要透视变换；没有此能力时使用支持透视的外部制作工具或原生图像网格，不将截图仅旋转后硬塞。
4. 屏幕截图的文字、配图和作者信息来自真实材料。场景生成不负责生成或改写内容。
5. 检查设备是否真正落在台面上、台面是否过薄或悬浮、是否有不合理横向接缝、阴影与设备是否同一方向。

素材只生成出包装并不代表已通过验收；看到实际合成效果后再决定保留或替换。

## 本地图标

优先用项目指定图库，先按文件名搜索语义，再查看实际 SVG。Nucleo 图库可从 `outline` 中找同尺寸的 shield-check、file-content、circle-check 等，不混用线性、填充和双色风格。

读取 SVG 后保留路径，只替换展示颜色。用 `createNodeFromSvg` 导入，通过 `rescale(目标尺寸/原宽)` 同比缩放；只对外层 `resize` 可能无法同比缩放路径。设置名称、父容器、位置，隐藏替代的旧图标，返回新图标和后代节点 ID。保留原 SVG 副本与来源路径。

18px 源图标放到 24px 视框时检查线宽，不因源名不同就修改原库。用户指定的文件夹是资源来源，不是默认可写位置。

## 一轮验收的范围

| 检查层 | 查看内容 |
| --- | --- |
| 结构返回值 | 节点、尺寸、数量、可见版本、文本内容、目标 Page |
| 整页截图 | 主次、加粗密度、分组亲密性、留白、构图节奏、背景与文字竞争 |
| 关键局部 | 图片缺失、图标、蒙版、字形、机框、入口、按钮、可见边缘对齐、容器内部重叠、旁注与引线对应 |
| 事实核对 | 来源屏幕、流程关系、职责、指标计算、样本与排除项 |

相关修改后截一次整页；发现问题再修正并重截。最后一次通过的截图就是本轮验收，不在无变化时重复。细节模糊时只放大对应节点，不重截整文件。
